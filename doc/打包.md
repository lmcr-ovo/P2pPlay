# Qt/CMake 通用打包文档

这份文档的目标是：学会把 Qt + CMake 项目里的任意 exe 打包成可以在没有 Qt、没有 CLion、没有配置环境变量的 Windows 电脑上运行的程序。

本文以当前媒体测试程序 `testV.exe` 为例，但方法不只适用于 `testV`。以后 `testP2pClient.exe`、正式客户端、服务端工具，只要是 Qt/CMake 目标，都可以按同一套流程打包。

## 一句话流程

```text
1. 用 MinGW 配置 Release 构建目录
2. 编译指定 target
3. 新建发布目录
4. 复制 exe 到发布目录
5. 用 windeployqt --release 收集 Qt dll
6. 手动复制 MinGW 运行库
7. 把整个发布目录发给别人
```

注意：发布时不要只发 exe，要发整个发布目录。

## 需要先知道的几个名字

打包前先确定三个东西：

```text
target 名
  CMake 里的目标名，例如 testV、testP2pClient、testP2pServer

exe 路径
  编译后生成的 exe 位置

发布目录
  准备发给别人的文件夹
```

以 `testV` 为例：

```text
target 名:
  testV

exe 路径:
  cmake-build-release\Client\test\testV.exe

发布目录:
  release-testV
```

## 1. 清理旧 Release 构建目录

如果之前配置失败过，建议先删掉旧目录，避免 CMake 缓存影响后续构建。

```bat
cd /d D:\CODE\C++\qt\P2Pplay
rmdir /s /q cmake-build-release
```

如果目录不存在，`rmdir` 报错可以忽略。

## 2. 配置 Release 构建

本项目使用 Qt MinGW，所以要明确指定：

```text
MinGW Makefiles
Qt MinGW 路径
gcc.exe
g++.exe
Release
```

完整命令：

```bat
"D:\CLion 2019.3.6\bin\cmake\win\bin\cmake.exe" ^
-S . ^
-B cmake-build-release ^
-G "MinGW Makefiles" ^
-DCMAKE_BUILD_TYPE=Release ^
-DCMAKE_PREFIX_PATH=D:/Qt5/5.14.0/mingw73_64 ^
-DCMAKE_C_COMPILER=D:/Qt5/Tools/mingw730_64/bin/gcc.exe ^
-DCMAKE_CXX_COMPILER=D:/Qt5/Tools/mingw730_64/bin/g++.exe
```

这里路径建议用 `/`：

```text
D:/Qt5/Tools/mingw730_64/bin/g++.exe
```

不要在 CMake 参数里写：

```text
D:\Qt5\Tools\mingw730_64\bin\g++.exe
```

因为 `\Q` 之类的内容可能被 CMake 当成非法转义。

## 3. 编译指定目标

通用格式：

```bat
"D:\CLion 2019.3.6\bin\cmake\win\bin\cmake.exe" --build cmake-build-release --target 目标名 -j 4
```

打包 `testV` 时：

```bat
"D:\CLion 2019.3.6\bin\cmake\win\bin\cmake.exe" --build cmake-build-release --target testV -j 4
```

其他例子：

```bat
"D:\CLion 2019.3.6\bin\cmake\win\bin\cmake.exe" --build cmake-build-release --target testP2pClient -j 4
```

```bat
"D:\CLion 2019.3.6\bin\cmake\win\bin\cmake.exe" --build cmake-build-release --target testP2pServer -j 4
```

## 4. 找到 exe

`testV` 的 exe 通常在：

```text
cmake-build-release\Client\test\testV.exe
```

如果不知道目标生成在哪里，可以搜索：

```bat
dir /s /b cmake-build-release\testV.exe
```

其他例子：

```text
cmake-build-release\Client\test\testP2pClient.exe
cmake-build-release\Server\test\testP2pServer.exe
```

## 5. 创建发布目录并复制 exe

通用格式：

```bat
rmdir /s /q 发布目录
mkdir 发布目录
copy "exe路径" "发布目录\"
```

`testV` 示例：

```bat
rmdir /s /q release-testV
mkdir release-testV
copy "cmake-build-release\Client\test\testV.exe" "release-testV\"
```

路径里有 `C++` 或空格时，务必加双引号。

## 6. 使用 windeployqt 收集 Qt 依赖

通用格式：

```bat
"D:\Qt5\5.14.0\mingw73_64\bin\windeployqt.exe" --release "发布目录\程序名.exe"
```

`testV` 示例：

```bat
"D:\Qt5\5.14.0\mingw73_64\bin\windeployqt.exe" --release "release-testV\testV.exe"
```

为什么要加 `--release`：

有时 `windeployqt` 会把 exe 误判成 debug executable，然后去找：

```text
Qt5Cored.dll
Qt5Networkd.dll
```

但普通 Qt 安装通常只有：

```text
Qt5Core.dll
Qt5Network.dll
```

所以如果你确定自己编译的是 Release 版，就加 `--release`。

## 7. 手动复制 MinGW 运行库

`windeployqt` 主要复制 Qt 的 dll，但 MinGW 自己的运行库建议手动补齐。

通用命令：

```bat
copy "D:\Qt5\Tools\mingw730_64\bin\libgcc_s_seh-1.dll" "发布目录\"
copy "D:\Qt5\Tools\mingw730_64\bin\libstdc++-6.dll" "发布目录\"
copy "D:\Qt5\Tools\mingw730_64\bin\libwinpthread-1.dll" "发布目录\"
```

`testV` 示例：

```bat
copy "D:\Qt5\Tools\mingw730_64\bin\libgcc_s_seh-1.dll" "release-testV\"
copy "D:\Qt5\Tools\mingw730_64\bin\libstdc++-6.dll" "release-testV\"
copy "D:\Qt5\Tools\mingw730_64\bin\libwinpthread-1.dll" "release-testV\"
```

## 8. 发布目录应该是什么样

以 `testV` 为例，发布目录大概是：

```text
release-testV/
  testV.exe
  Qt5Core.dll
  Qt5Network.dll
  libgcc_s_seh-1.dll
  libstdc++-6.dll
  libwinpthread-1.dll
```

如果以后用了 GUI，可能还会有：

```text
Qt5Gui.dll
Qt5Widgets.dll
platforms/
styles/
imageformats/
```

这些都要一起发，不能只发 exe。

## 9. 运行打包后的 testV

Host：

```bat
release-testV\testV.exe host Alice 119.45.223.242 9000 9001 10000
```

Guest：

```bat
release-testV\testV.exe guest Bob 房间号 119.45.223.242 9000 9001 10001
```

成功时 Guest 应该能持续看到伪视频数据：

```text
hello
hello
hello
```

这说明：

```text
P2P 打洞成功
MediaService 启动成功
Host 发送 VideoFrame 成功
Guest 接收 VideoFrame 成功
```

## 11. 常见错误

### 找不到 cl

错误：

```text
The CMAKE_C_COMPILER: cl is not a full path and was not found in the PATH.
```

原因：

```text
CMake 默认选择了 NMake Makefiles
NMake 需要 Visual Studio 的 cl.exe
但当前 shell 没有 VS 编译环境
```

解决：

```bat
-G "MinGW Makefiles"
```

并指定：

```bat
-DCMAKE_C_COMPILER=D:/Qt5/Tools/mingw730_64/bin/gcc.exe
-DCMAKE_CXX_COMPILER=D:/Qt5/Tools/mingw730_64/bin/g++.exe
```

### Invalid character escape '\Q'

错误：

```text
Invalid character escape '\Q'
```

原因：

```text
CMake 参数里用了 Windows 反斜杠路径
D:\Qt5\...
```

解决：

```text
把 CMake 参数里的路径改成正斜杠
D:/Qt5/...
```

### Qt5Cored.dll does not exist

错误：

```text
Qt5Cored.dll does not exist.
```

原因：

```text
windeployqt 把 exe 判断成 debug executable
于是去找 debug Qt 库
```

解决：

```bat
"D:\Qt5\5.14.0\mingw73_64\bin\windeployqt.exe" --release "发布目录\程序名.exe"
```

### 别人电脑提示缺 dll

常见缺失：

```text
Qt5Core.dll
Qt5Network.dll
libgcc_s_seh-1.dll
libstdc++-6.dll
libwinpthread-1.dll
```

解决：

```text
1. 确认运行过 windeployqt --release
2. 确认手动复制了 MinGW 三个运行库
3. 确认发给别人的是整个发布目录，不是单个 exe
```

### copy 命令语法不正确

常见原因：

```text
路径里有 C++、空格或特殊字符，但没有加双引号
```

解决：

```bat
copy "cmake-build-release\Client\test\testV.exe" "release-testV\"
```

## 12. 通用打包模板

```text
目标名
exe路径
发布目录
```

模板：

```bat

rmdir /s /q cmake-build-release

"D:\CLion 2019.3.6\bin\cmake\win\bin\cmake.exe" ^
-S . ^
-B cmake-build-release ^
-G "MinGW Makefiles" ^
-DCMAKE_BUILD_TYPE=Release ^
-DCMAKE_PREFIX_PATH=D:/Qt5/5.14.0/mingw73_64 ^
-DCMAKE_C_COMPILER=D:/Qt5/Tools/mingw730_64/bin/gcc.exe ^
-DCMAKE_CXX_COMPILER=D:/Qt5/Tools/mingw730_64/bin/g++.exe

"D:\CLion 2019.3.6\bin\cmake\win\bin\cmake.exe" --build cmake-build-release --target 目标名 -j 4

copy "exe路径" "发布目录\"

"D:\Qt5\5.14.0\mingw73_64\bin\windeployqt.exe" --release "发布目录\程序名.exe"
```
