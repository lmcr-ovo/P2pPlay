可以，你现在最需要建立一个“视频参数计算脑图”。远控视频其实就是在算这几个核心量：

```text
FPS
分辨率
单帧大小
码率
延迟
丢帧率
编码耗时
网络带宽
```

**1. FPS 是什么**

FPS = Frames Per Second，意思是每秒多少帧。

```text
30 FPS = 每秒 30 张画面
50 FPS = 每秒 50 张画面
60 FPS = 每秒 60 张画面
```

每帧之间的时间间隔：

```text
frameIntervalMs = 1000 / FPS
```

所以：

```text
30 FPS -> 1000 / 30 = 33.3 ms/帧
50 FPS -> 1000 / 50 = 20 ms/帧
60 FPS -> 1000 / 60 = 16.7 ms/帧
```

这意味着如果你想做 50 FPS，那么：

```text
采集 + 编码 + 发送调度
最好每 20ms 完成一次
```

否则就会掉帧。

**2. 分辨率是什么**

分辨率就是画面宽高。

比如：

```text
1920x1080 = 2073600 像素
1280x720  = 921600 像素
960x540   = 518400 像素
```

像素数计算：

```text
pixels = width * height
```

1080p 像素数约是 720p 的：

```text
2073600 / 921600 = 2.25 倍
```

所以 1080p 的采集、编码、传输压力大概比 720p 高很多。

**3. 原始帧大小怎么算**

如果是 RGB/BGRA 原始图像：

```text
RGB  = 每像素 3 字节
BGRA = 每像素 4 字节
```

公式：

```text
rawFrameSize = width * height * bytesPerPixel
```

例如 1280x720 BGRA：

```text
1280 * 720 * 4 = 3686400 bytes
约 3.5 MB/帧
```

如果 50 FPS 不压缩直接传：

```text
3.5 MB * 50 = 175 MB/s
约 1400 Mbps
```

这肯定不现实。

所以必须压缩。

**4. JPEG 单帧大小和码率**

JPEG 压缩后，单帧大小可能是：

```text
720p quality 50:
几十 KB 到几百 KB
```

假设一帧 JPEG 是 100 KB，50 FPS：

```text
100 KB * 50 = 5000 KB/s
约 5 MB/s
约 40 Mbps
```

换算公式：

```text
MB/s = frameSizeKB * FPS / 1024
Mbps = MB/s * 8
```

例子：

```text
50 KB * 50 FPS = 2500 KB/s = 2.44 MB/s = 19.5 Mbps
100 KB * 50 FPS = 5000 KB/s = 4.88 MB/s = 39 Mbps
200 KB * 50 FPS = 10000 KB/s = 9.77 MB/s = 78 Mbps
```

所以你要冲 50 FPS，要重点控制：

```text
单帧压缩后大小
```

**5. H.264 码率怎么算**

H.264 通常不是按“每帧多少 KB”控制，而是按码率控制：

```text
bitrate = 每秒多少 bit
```

常见单位：

```text
Mbps = megabits per second
```

例如：

```text
5 Mbps
10 Mbps
20 Mbps
```

换算：

```text
1 Byte = 8 bits
1 MB/s = 8 Mbps
```

所以：

```text
10 Mbps = 1.25 MB/s
20 Mbps = 2.5 MB/s
```

如果 50 FPS、10 Mbps：

```text
平均每帧大小 = 10 Mbps / 50
             = 0.2 Mbit/帧
             = 25 KB/帧
```

公式：

```text
avgFrameSizeKB = bitrateMbps * 1024 / 8 / FPS
```

例子：

```text
10 Mbps, 50 FPS:
10 * 1024 / 8 / 50 = 25.6 KB/帧

20 Mbps, 50 FPS:
20 * 1024 / 8 / 50 = 51.2 KB/帧

10 Mbps, 30 FPS:
10 * 1024 / 8 / 30 = 42.7 KB/帧
```

这就是 H.264 比 JPEG 强的地方：同样画质下，平均帧大小小很多。

**6. 延迟怎么算**

端到端延迟：

```text
latency = Guest收到时间 - Host采集时间
```

所以视频帧 payload 里要带：

```cpp
captureTimestampMs
```

发送时：

```cpp
frame.captureTimestampMs = QDateTime::currentMSecsSinceEpoch();
```

接收时：

```cpp
qint64 now = QDateTime::currentMSecsSinceEpoch();
qint64 latencyMs = now - frame.captureTimestampMs;
```

延迟由这些部分组成：

```text
采集耗时
编码耗时
发送排队耗时
网络传输耗时
接收合片耗时
解码耗时
渲染等待耗时
```

公式大概是：

```text
totalLatency =
    captureCost +
    encodeCost +
    sendQueueDelay +
    networkDelay +
    reassembleDelay +
    decodeCost +
    renderDelay
```

远控比较舒服的目标：

```text
< 50ms  很好
50-100ms 可用
100-200ms 勉强
> 200ms 明显迟钝
```

**7. 丢帧率怎么算**

如果视频帧号是：

```text
1, 2, 3, 4, 5...
```

Guest 收到：

```text
1, 2, 4, 5
```

说明丢了 3。

计算：

```text
lostFrames = currentSeq - lastSeq - 1
```

总丢帧率：

```text
lossRate = lostFrames / expectedFrames
```

例如应该收到 1000 帧，丢了 20 帧：

```text
20 / 1000 = 2%
```

**8. 你现在最应该记录的日志**

每收到一帧打印或统计：

```text
seq
payload size
latency ms
fps
lost frames
```

比如：

```text
video seq=1024 size=58KB latency=43ms fps=49 lost=2
```

FPS 统计可以每秒算一次：

```cpp
framesThisSecond++;
if (timer.elapsed() >= 1000) {
    qDebug() << "fps:" << framesThisSecond;
    framesThisSecond = 0;
    timer.restart();
}
```

**9. 推荐初始参数**

你想冲 50 FPS，可以先这样：

```text
分辨率：1280x720
FPS：50
JPEG quality：45
目标单帧大小：50KB - 120KB
目标码率：20Mbps - 50Mbps
```

如果卡：

```text
先降 quality
再降分辨率
再降 FPS
```

调参优先级：

```text
1. quality
2. resolution
3. FPS
```

**10. 最重要的公式汇总**

```text
每帧间隔:
frameIntervalMs = 1000 / FPS

像素数:
pixels = width * height

原始帧大小:
rawBytes = width * height * bytesPerPixel

JPEG 估算码率:
Mbps = frameSizeKB * FPS * 8 / 1024

H.264 平均每帧大小:
avgFrameSizeKB = bitrateMbps * 1024 / 8 / FPS

端到端延迟:
latencyMs = receiveTimestampMs - captureTimestampMs

丢帧数:
lost = currentSeq - lastSeq - 1
```

你现在可以先把这些参数做进 `VideoFramePayload` 和日志里。  
一旦能看到：

```text
fps
sizeKB
latencyMs
lost
```

你就能开始真正调视频效果了。
